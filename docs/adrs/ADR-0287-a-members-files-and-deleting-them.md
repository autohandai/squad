# ADR-0287: A member's files, and deleting them

Status: accepted, 2026-11-26

## Context

The owner: "an agent profile we should be able to see all files generated by
that agent, image, docs etc. so users can delete manually if they want to."

What existed: a member's Library (ADR-0176) lists files it *published* with
`squad_publish_artifact`, with open and download, but no delete. Nothing
recorded the other files a member writes. Change batches (ADR-0161) see the
Autohand Code engine's staged writes during a turn but keep nothing after it,
and see nothing from the shell, Claude Code, Codex or other engines.

## Decision

- **Record after every turn, on every engine.** `executeChatTurnInner` (the
  one path every engine's turn takes) now notes when the turn started and,
  after it ends, looks in the member's folders (its workspace and granted
  projects) for files changed since then: `git status` for repositories
  (follows .gitignore), a bounded walk elsewhere (skips dependency and build
  folders, never the home folder or a system root). Each file is recorded
  against the member as created (born during the turn) or edited, in
  `<state>/member-files/<member>.json` (0600, newest 2000). The scan runs
  after the reply, has a 2.5 s budget and never fails or delays it.
- **One page.** The member's Library keeps its published files and gains
  "Made in its folders": name, path from home, created or edited, kind
  (image, document, code, data, audio or video), size and date.
- **Deleting.** A published file can be deleted (two clicks): its record
  goes, its saved bytes too unless another record shares them; the member's
  original workspace file is not touched. A file the member *created* can be
  moved to the Trash (`/usr/bin/trash` on macOS, Finder as a fallback, `gio
  trash` on Linux), so it can be put back. Only paths in that member's
  record, still inside the folder they were found in.
- **Edited files are not offered for deletion.** They existed before the
  member touched them; the page says the member edited them.

## Consequences

- Files made before this release are not listed; the record starts now.
- Two members working in the same folder at the same time can both be
  credited with a file the other wrote.
- A member that edits a file it created earlier keeps it as created; a file
  a person creates in a member's folder during that member's turn is credited
  to the member. The page shows the path so the person can judge.
- Files outside the member's folders (for example `/tmp`) are not seen.
- Generated chat images and attachments are not part of this page yet.

Evidence: `node scripts/check-member-files.mjs` (a git repository and a plain
folder: three changed files recorded, `node_modules` and the home folder
skipped, created vs edited from birth time, per-member records at 0600, Trash
refused for edited files, unknown paths and another member, deleted files
drop out, an artifact deleted while another record shares its bytes keeps
them, the last one removes them, the original file untouched).
`check:artifacts`, `check:server`, `check:render` and the build pass.
